# 01. Обзор проекта

## Что это
**BeruTUT** — учебный/портфолио интернет-магазин: публичная часть (каталог, корзина, оформление заказа) + админ-панель (товары, категории, заказы, пользователи). Один репозиторий: `backend/` (.NET 8), `frontend/` (React), `docs/`. Исходное ТЗ — `TECH_SPEC.md` (10 этапов; все реализованы, кроме деплоя).

Репозиторий: `https://github.com/art-mrx/BeruTUT`, ветка `main` (единственная). Владелец/пользователь — art-mrx, общается **по-русски**.

## Стек (реально установленные версии)
**Backend:** .NET 8 (в системе стоят SDK 8/9/10; проекты таргетят `net8.0`, `global.json` нет), ASP.NET Core Web API, EF Core **8.0.11** + Npgsql (все EF/ASP.NET-пакеты нарочно пиннятся на 8.0.11 — без версии подтянется 10.x, несовместимый с net8.0), PostgreSQL 18 (локальная Windows-служба), MediatR 12.4.1, AutoMapper 13.0.1 (новее — платная лицензия; предупреждение NU1903 при сборке — известное, игнорируем), FluentValidation 11.9.2, Serilog, Swashbuckle 6.6.2, xUnit + Moq + FluentAssertions + EF InMemory. Решение — `backend/Store.slnx` (новый XML-формат).
**Frontend:** React **18.3.1** (ТЗ требует 18), Vite 8, TypeScript ~6.0, React Router **v7** (осознанное отклонение от v6 из ТЗ: в v6 две CVE), TanStack Query v5, Zustand v5, React Hook Form + Zod v4, Tailwind **v4** (через `@tailwindcss/vite`, без tailwind.config), Axios, oxlint.

## Как запустить (разработка)
Два терминала:
```powershell
cd backend\src\Store.Api ; dotnet run --urls "http://localhost:5080"     # backend, Swagger: /swagger
cd frontend ; npm run dev                                                # frontend :5173, проксирует /api и /uploads на :5080
```
Тесты: `cd backend ; dotnet test` (66 тестов). Сборка фронтенда: `cd frontend ; npm run build` (`tsc -b` + vite), линт `npm run lint`.
Первичная настройка БД/секретов — в корневом `README.md`. Секреты (`Jwt:SigningKey`, `AdminSeed:Password`) — **`dotnet user-secrets` в терминале пользователя** (см. грабли в 05).

## Данные в локальной БД (dev)
- Admin: `admin@store.local` (создаётся сидером при старте в Development). **Пароль в репозиторий не кладём.** Пользователь его знает; в окружении Claude он лежит в user-secrets `AdminSeed:Password` (`dotnet user-secrets list --project backend/src/Store.Api`).
- Покупатель: `buyer1@example.com` / `Password123` (у него ~7 заказов в разных статусах).
- Категория Electronics, ~10 товаров (Gaming Laptop, USB-C Hub, Wireless Mouse и т.д., цены $5–$2000), у товаров нет картинок (загрузка — через админку).
- Тестовые данные оставлены намеренно как образцы; ничего «чистить» не нужно.
- БД: роль/БД `store`, пароль `store` (несекретный локальный), `psql -U store -h localhost -d store`. В pgAdmin таблицы нужно цитировать: `select * from "Products";`.

## Договорённости с пользователем (обязательно соблюдать)
1. **Пуш после каждого коммита** в `main` — без вопросов. **Не добавлять Claude как соавтора** (`Co-Authored-By`) ни в коммиты, ни в PR. Force-push в `main` Claude сам **не делает** — готовит команду, пользователь выполняет.
2. **После каждой доработки обновлять** `docs/PROGRESS.md`, `docs/DECISIONS.md` и `docs/context/04-state-and-backlog.md` (пользователь просил это специально, чтобы новый диалог не «перекапывал» проект).
3. **Проверять до того, как сказать «готово»**: тесты + реальный прогон (HTTP по настоящей БД и/или в браузере, включая мобильную ширину). Для бизнес-логики — юнит-тесты (ТЗ п.9). Честно сообщать о найденных багах и отклонениях от ТЗ (пользователь ценит «как сделал бы senior»).
4. **Не вводить чужие пароли/секреты** самому: если нужен пароль пользователя (например `postgres`) — он вводит его сам в своём терминале. Секреты в git не попадают.
5. **Деплой отложен** по решению пользователя — не предлагать снова без повода.
6. Язык: интерфейс и документация — русские; тексты API-ошибок и код — английские; коммиты — английские, развёрнутые («почему», не только «что»).
7. Если нужно остановить его запущенный backend (миграции/сборка) — **попросить пользователя нажать Ctrl+C**, самому убить процесс не получится (см. 05).
8. Отвечать кратко, без воды; итог — что сделано, что нужно от пользователя, что важно знать.
