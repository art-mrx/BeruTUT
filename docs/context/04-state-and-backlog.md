## Известные ограничения / осознанные упрощения
- **Нет защиты от гонки за остаток** (нет `RowVersion`/optimistic concurrency): два одновременных заказа на последнюю единицу теоретически оба пройдут.
- Очередь «Ожидают подтверждения» по умолчанию — от новых к старым (для обзвона удобнее «сначала старые»; сортировка переключается вручную).
- «Номер» заказа/пользователя — первые 8 символов Guid, сквозной нумерации нет.
- Поиск в админке: заказы — только по номеру; пользователи — по имени/email/номеру. По телефону клиента искать нельзя.
- Блокировка пользователя **не трогает его ожидающие заказы** — они остаются в очереди.
- Нет гостевой корзины (только для авторизованных), нет отзывов/рейтингов, платежей, email-уведомлений, мультиязычности (вынесено ТЗ п.10 за рамки MVP).
- Токены хранятся в `localStorage` (компромисс SPA; альтернатива — httpOnly cookie + BFF).
- Загрузка изображений — на локальный диск; удаления отдельной картинки нет (только добавление).
- Проверка статуса пользователя на **каждом** запросе (см. 02) — приемлемо для масштаба проекта, при росте — кэш.
- Docker-файлы (`Dockerfile`, `docker-compose.yml`) написаны, но **ни разу не запускались** (у пользователя Docker не работает); frontend-сервис в compose закомментирован.
- Favicon и `frontend/public/icons.svg` — **остатки шаблона Vite** (фиолетовая молния); не заменены, `icons.svg` нигде не используется.

## С чего начинать новый диалог
1. Прочитать эту папку (порядок в [README.md](README.md)), особенно **05** (грабли).
2. `git log --oneline -10` и `git status` — убедиться, что рабочее дерево чистое и синхронизировано с `origin/main`.
3. Для проверки живого состояния: поднять backend (см. 05: сборка не должна конфликтовать с процессом пользователя) и прогнать `dotnet test`.
4. Любую доработку завершать по договорённостям из 01: тесты → реальная проверка → docs → коммит → пуш.
