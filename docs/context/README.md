# Контекст проекта BeruTUT (для нового диалога)

Эта папка — «передача дел»: всё, что нужно, чтобы новый диалог с Claude (или новый разработчик) понял проект без перечитывания старой переписки. Читать **по порядку**:

| Файл | О чём |
|---|---|
| [01-overview.md](01-overview.md) | Что за проект, стек, как запустить, тестовые аккаунты, **договорённости о работе с пользователем** |
| [02-architecture.md](02-architecture.md) | Как устроены backend и frontend, сквозные паттерны, безопасность |
| [03-domain-and-api.md](03-domain-and-api.md) | Доменная модель, бизнес-правила (статусы заказов, остатки), полный список эндпоинтов |
| [04-state-and-backlog.md](04-state-and-backlog.md) | Что сделано, что нет, известные ограничения, идеи на будущее |
| [05-environment-and-gotchas.md](05-environment-and-gotchas.md) | **Грабли окружения** (Windows/инструменты Claude) и рецепты проверки — читать до первой команды |

Более подробные журналы (не заменяются этой папкой, а дополняются ею):
- [../PROGRESS.md](../PROGRESS.md) — чек-листы по каждому этапу и доработке;
- [../DECISIONS.md](../DECISIONS.md) — обоснования решений, отклонения от ТЗ, найденные баги;
- [../../TECH_SPEC.md](../../TECH_SPEC.md) — исходное ТЗ;
- [../../README.md](../../README.md) — инструкция запуска для человека.

## Как поддерживать актуальность
После каждой заметной доработки: обновить `PROGRESS.md` (чек-лист) и `DECISIONS.md` (почему так), а здесь — `04-state-and-backlog.md` (состояние), а при изменении архитектуры/API/правил — `02` или `03`. Не дублировать сюда то, что легко прочитать из кода (имена файлов, сигнатуры) — только то, что из кода не видно: почему, договорённости, грабли.

Актуально на: **2026-09-21**, коммит `6e57032` (ветка `main`, репозиторий `art-mrx/BeruTUT`).
